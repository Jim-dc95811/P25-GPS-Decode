P25 Receive-Side Test Patterns

What each pattern is, what it's for, and how we use them to measure 5% BER sensitivity.
VIAVI 8800SX · P25 Phase 1 · 2026-11-25

1Why a known pattern at all

BER (Bit Error Rate) is simply errored bits ÷ total bits, as a percent. To count errors you have to know what was supposed to arrive — so the generator sends a defined bit sequence and the receiver compares what it decoded against that known reference. The P25 reference sensitivity point is a 5% BER: the weakest RF level at which a receiver still decodes with no more than 5% of its bits wrong (typically −116 to −120 dBm for a good Phase-1 radio). Different patterns serve different jobs in getting to that number.

2The four patterns on the 8800SX

STD 1011 clean · 0% built-in

Standard Tone Test Pattern (TIA-102)

A defined sequence weighted toward the 00/01 dibits that decodes to a clean ~1011 Hz tone. No injected errors.

Use: audio/functional check, deviation & frequency (AFC) reference, and the baseline for a sensitivity sweep — it reads 0% on a strong signal, and you lower the level until noise drives it to 5%.

STD CAL ~4.98% built-in

Calibration Test Pattern (TIA-102)

STD 1011 with every 20th bit intentionally inverted → exactly 172 errored bits per 3,456 = 4.977% BER by construction, at any signal level.

Use: calibrate the BER meter. At a strong level it must read ~4.98% — that proves the error counter is accurate before you trust it on a real sweep. It is not a sensitivity pattern and never reads 0%.

STD 511 / O.153 PRBS-9 · BER sweep

511-bit pseudo-random (ITU-T O.153, ex-V.52)

A 511-bit PRBS (PRBS-9) — every symbol transition exercised evenly, simulating real random traffic. No injected errors.

Use: the rigorous sensitivity-sweep pattern (the standard way to find the ≤5% reference sensitivity). ~0% on a strong signal, climbs with noise. Note: it's not voice frames, so a normal radio won't unmute on it — a radio's own BER readout needs OEM test mode. (Our DEO tap reads the symbols regardless — see §5.)

STD Silence digital silence

Valid voice frames at zero audio (TIA-102)

A valid P25 LDU voice-frame structure carrying IMBE/AMBE frames at zero audio level — real framing, headers and NAC, just silent.

Use: audio noise floor, squelch, and receiver unmute verification (residual audio-noise ratio, TIA-102.CAAA). Because it carries valid NAC/framing without OEM software, it confirms a radio decodes the NAC and holds squelch open cleanly. Not a BER pattern.

The gotcha: CAL is not a clean baseline — its ~5% is baked into the bits, independent of RF level. If you want a true 0% reference, that's 1011. CAL exists to prove your 5% mark is honest.

4The 5% BER sensitivity test — correct order of operations

  1. Calibrate the meter — STD CAL at a strong level (e.g. −90 dBm). The counter must read ~4.98%. That confirms the error count itself is trustworthy.
  2. Baseline the decoder — STD 1011 at the same strong level. It must read 0%. That confirms the whole receive + decode chain is clean with a good signal.
  3. Sweep — STD 511 / O.153 (the rigorous PRBS pattern; 1011 also works), step the RF level down. BER climbs as the signal approaches the noise floor. The level where it crosses 5% is the sensitivity.
  4. Record that level. Compare it against the reference radio's 5% level measured on the same generator, same calibration — a true head-to-head.

The test set reads a radio's BER only if the radio exposes a BER test mode / data output (or loops the signal back). Our method doesn't need that — see §5.

5How we run it (DEO tap → software)

We don't use the radio's internal BER meter, and we don't need the radio in OEM test mode — the standard requirement for a radio to report its own BER. The VIAVI feeds the reference pattern into the host radio; we tap the detector output (DEO), capture it on a sound card, and our software recovers the symbols and counts errors against the known pattern. We are the BER meter, reading the detected symbols directly (muted or not). The same two baselines apply to our measuring chain:

6Raw vs corrected — where our edge actually is

The 5% sensitivity number is a channel (pre-FEC) BER — symbol/bit errors straight off the demodulator. Here a good radio and our MMSE recovery both sit near the theoretical optimum, so the honest expectation is that we match the reference radio — a PC tying purpose-built hardware. The place a decoder can pull ahead is the corrected (post-FEC) / message layer, where soft-decision Viterbi reclaims coding gain a hard-decision firmware leaves on the table. That's the GPS-frame success test, not the raw-pattern BER — run both, and keep the claims separate.

Both radios share the same −120 dBm noise floor (physics). This is a coding-efficiency contest — who decodes nearest the floor — not a sensitivity contest. We don't beat thermal noise; we close the gap to it.
