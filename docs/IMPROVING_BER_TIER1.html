Improving BER in Tier-1 GPS Decoding

Soft-decision error correction for over-the-air P25 position decode
built by Claude McNally · for Jim · 2026-11-24
In one breath. The Universal Traveler / Traveler PC decodes a radio's GPS straight off the air. The decoder we shipped works, but it makes a hard decision: it rounds each received symbol to the nearest of four levels before the error-correction stage, discarding how confident that symbol was. If instead we keep that confidence and hand it to the error corrector — a soft decision — the decoder tolerates a weaker signal for the same reliability. Measured on our exact error-correcting code, that is worth 3.2 dB. For a firefighter at the edge of radio range, 3 dB is the difference between their position plotting and not.

1. Why this matters: bit-error tolerance is range

Every GPS report that comes over the air is a string of symbols, and noise flips some of them. Bit-error rate (BER) is how often that happens; the error-correcting code (FEC) in P25 is designed to repair a certain number of flips and recover the exact position and unit ID. When noise exceeds what the FEC can fix, the whole report is lost — the dot does not appear.

The unit you most need to see is almost always the one with the weakest signal: farthest out, down in a draw, behind a ridge. So “how many bit errors can the decoder survive” is not an abstraction — it is the usable range of the whole safety system. Buying a few dB of error tolerance directly extends how far out a crew member can be and still show up on the map.

2. Where the current decoder leaves accuracy on the table

Our signal chain is: radio detector audio → symbol recovery (a tracking loop that produces a clean, analog estimate of each 4-level symbol) → slice to the nearest level → frame sync → FEC (Viterbi) → NMEA position.

The loss happens at the slice. The symbol recovery knows not just “this looks like a +1” but how close it was — dead-on +1, or a mushy +0.3 that was nearly a −1. That closeness is a confidence. The moment we round to the nearest level we throw it away, and from there the frame sync (a bit-by-bit match) and the FEC (a hard-decision Viterbi, counting mismatched bits) work only on hard 1s and 0s. A symbol the decoder was 95% sure of and one it was 51% sure of are treated identically.

Hard vs soft, in one sentence

Hard decision throws away the confidence and corrects bits. Soft decision keeps the confidence and lets the error corrector trust the strong symbols and lean on them to fix the weak ones. It is the single most established way to get more out of the same received signal — textbook ~2 dB, and more on a short code like this one.

3. The fix — same code, a better yardstick

Nothing about the P25 standard, the trellis, or the tables changes. The only change is the yardstick the Viterbi error corrector uses to score each candidate:

  • Soft-decision Viterbi — replace “how many bits differ” (Hamming distance on sliced bits) with “how far were the actual soft symbols from the ideal levels” (Euclidean distance). Applied to both the rate-½ and rate-¾ data blocks.
  • Soft frame sync — lock onto the burst by correlating the soft symbol stream against the known sync pattern, instead of a hard bit-count. This catches noisier burst onsets — the exact failure seen in a real field capture. (A working version already exists in the project; it simply was never promoted into the live decoder.)
  • Key-up DC tracker — follow the small, decaying DC offset that the radio's audio coupling produces at the start of each transmission, which otherwise distorts the sync region.

4. The proof — measured, not asserted

To be sure this is real before building it everywhere, I ran a controlled experiment on our actual error-correcting code:

  • Built a P25 rate-½ encoder — the exact inverse of our decoder — and confirmed a clean round-trip (300/300 blocks recovered with no noise).
  • Pushed thousands of GPS data blocks through simulated radio noise at a sweep of signal levels.
  • Decoded every block two ways: with our shipping hard decoder (used verbatim) and with the soft decoder (same trellis and tables, Euclidean yardstick).

5. Honest boundaries

  • This is a clean simulation (Gaussian noise). A real discriminator tap has non-Gaussian noise, the key-up transient, and the receiver's own noise floor, so the field gain will be somewhat less than 3.2 dB. The direction and order of magnitude hold; the exact number must be measured on a real capture, not claimed.
  • It is coding gain, not magic. It extends the usable edge; it cannot recover a burst the receiver never truly heard. A genuinely dead stretch of signal stays dead.
  • On a strong signal there is no visible change — a clean capture already decodes 100%. The entire benefit shows up at the margin, which is exactly where safety is decided.
  • The front end still sets the floor. A clean tap (good level, no clipping, audio “enhancements” off) can be worth as much as the software change; the two are complementary.

6. What it buys

3.2 dB is roughly 40–50% more range in open country, or the difference between decoding a unit at the far edge of the repeater footprint and losing it. Framed for the mission: it is the weakest, farthest crew member — the one the safety system exists for — appearing on the map instead of dropping off it.

7. Build plan & status

  • Proven (this document): the soft-decision coding gain on our exact FEC, in controlled simulation — 3.2 dB. The decision gate (“is it worth it or are we reinventing the wheel?”) is cleared: it is worth it.
  • Next (software): carry the soft symbol confidence from the symbol-recovery stage through to both Viterbi routines (rate ½ and ¾), promote the soft frame-sync correlation into the live decoder, and add the key-up DC tracker. The algorithm structure is unchanged; only the metric and the sync search change.
  • Then (field proof): measure the real gain on a weak/marginal capture plus its reference answer-key log — a clean before/after on bursts the current decoder drops — and confirm no regression on a strong capture.
  • Platform: prove and run it on the PC first (ample compute). The router can likely carry it too, since soft Viterbi is a modest cost on a 4-state code and the box already keeps up with margin; decide after the PC result.

Glossary

BER / BLER
Bit-error rate / block-error rate — how often a single bit, or a whole GPS block, comes through wrong. A lost block = no dot on the map.
FEC (forward error correction)
Extra structure the transmitter adds so the receiver can repair a limited number of errors without asking for a resend. P25 uses trellis-coded FEC.
Viterbi decoder
The standard, optimal way to undo trellis FEC: it finds the most likely original message given the received symbols.
Hard vs soft decision
Hard = round each symbol to a bit first, then correct. Soft = keep each symbol's analog confidence and let the corrector weigh it. Soft is strictly more informed.
Coding gain
How much weaker a signal (in dB) the decoder can tolerate for the same reliability, thanks to a better decoding method. Here: 3.2 dB.
Es/N0
Signal-to-noise per symbol, in dB — the x-axis of the plot. Higher = stronger/cleaner signal.
Euclidean vs Hamming metric
The yardstick inside the Viterbi. Hamming counts differing bits (hard). Euclidean measures real distance from the ideal levels (soft).
AWGN
Additive white Gaussian noise — the standard clean-noise model used to measure a decoder fairly in simulation.
C4FM / dibit
The P25 modulation: four signal levels, each carrying 2 bits (a “dibit”).
